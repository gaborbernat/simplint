## What it does

Checks test modules for top-level classes that define a method whose name starts with `test`. A file is a test module
when its name starts with `test_`, ends with `_test.py`, is `conftest.py`, or sits under a `tests` or `test` directory.

## Why is this bad?

A test class adds a level of nesting and a `self` that most tests never use, and invites shared state through attributes
and setup methods. Module-level functions with the class name folded into a prefix keep the grouping visible in the test
name.

## Example

```python
class TestParser:
    def test_handles_empty(self) -> None:
        assert parse("") == []
```

Use instead:

```python
def test_parser_handles_empty() -> None:
    assert parse("") == []
```

## Fix safety

The fix is always unsafe: it renames every test, which changes its node ID and breaks `-k` selections or deselect lists
that name it, and it drops the class docstring. The prefix is the class name without its leading `Test`, in snake case.
No fix is offered when the class has bases or decorators, holds a multi-line string, has anything but test methods in
its body, or when a method uses `self`, has no `self` parameter, takes positional-only parameters, or would get a name
already used in the file.
