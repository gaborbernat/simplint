## What it does

Checks for `try` statements whose body holds only imports of required modules and that have an `except` handler catching
`ImportError` or `ModuleNotFoundError`, alone or in a tuple. A module is required when its top-level package is in the
standard library of the target Python version, is listed in `project.dependencies` of `pyproject.toml`, or is the
package the file belongs to; relative imports count as the project's own. Requirements with an environment marker (`;`)
are conditional and do not count. Dependencies are matched by their normalized distribution name and, for well-known
distributions that import under another name, by that name too, such as `PyYAML` as `yaml`, `Pillow` as `PIL` or
`beautifulsoup4` as `bs4`; other renamed distributions are not recognized. Modules that exist on one platform only, such
as `fcntl`, `msvcrt` or `winreg`, never count as required.

## Why is this bad?

A required dependency is always installed, so the fallback never runs in a working environment. When the install is
broken, the guard hides the import error until something later fails with a less clear message.

## Example

```python
try:
    import requests
except ImportError:
    requests = None
```

Use instead:

```python
import requests
```

## Fix safety

The fix replaces the `try` statement with its dedented body and drops every `except` handler. It is always unsafe,
because the fallback code is removed and a failing import now raises. No fix is offered when the statement has an `else`
or `finally` clause, or shares a line with other code.
