## What it does

Checks for `from __future__ import annotations` at module level when the target version is Python 3.14 or newer.

## Why is this bad?

Since Python 3.14 annotations are evaluated lazily by default, so the import no longer avoids forward-reference errors
or import cost. It only turns annotations into strings for code that inspects them at runtime.

## Example

```python
from __future__ import annotations, generator_stop
```

Use instead:

```python
from __future__ import generator_stop
```

## Fix safety

The fix removes `annotations` from the import, or deletes the statement when `annotations` is its only name (replacing
it with `pass` when it is the only statement in the module). No fix is offered when that statement shares its line with
other code. Code that reads `__annotations__` and expects strings gets evaluated objects afterwards. The fix is unsafe
when the module mentions `TYPE_CHECKING`, because lazy annotations are still evaluated on access, and one that names
something imported only for type checking raises `NameError` there; otherwise it is safe.
