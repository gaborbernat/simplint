## What it does

Checks for `from __future__ import annotations` at module level when the target version is Python 3.14 or newer.

## Why is this bad?

Since Python 3.14 annotations are evaluated lazily by default, so the import no longer avoids forward-reference errors
or import cost. It only turns annotations into strings for code that inspects them at runtime.

## Example

```python
from __future__ import annotations, generator_stop
```

Use instead:

```python
from __future__ import generator_stop
```

## Fix safety

The fix is safe. It removes `annotations` from the import, or deletes the statement when `annotations` is its only name
(replacing it with `pass` when it is the only statement in the module). Code that reads `__annotations__` and expects
strings gets evaluated objects afterwards, and an annotation that names something imported only under `TYPE_CHECKING`
raises `NameError` when inspected with the default format.
