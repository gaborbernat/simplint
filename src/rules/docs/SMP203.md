## What it does

Checks for attributes assigned on a mock right after it is created with `Mock`, `MagicMock`, `AsyncMock`,
`NonCallableMock`, `NonCallableMagicMock` or `create_autospec`. Only the run of `mock.attr = value` statements directly
following the creation is reported. The run stops at an attribute the constructor treats specially (`spec`, `spec_set`,
`wraps`, `name`, `parent`, `unsafe`, `instance`, `_name`, `_parent`), at a repeated attribute, or at a value that refers
to the mock itself.

## Why is this bad?

Setting attributes after construction spreads the mock's configuration over several statements. Passing them as keyword
arguments puts the whole setup in one call.

## Example

```python
fetch = create_autospec(fetch_user)
fetch.return_value = user
fetch.side_effect = None
```

Use instead:

```python
fetch = create_autospec(fetch_user, return_value=user, side_effect=None)
```

## Fix safety

The fix is safe. It moves the assignments into the constructor call as keyword arguments and deletes them; an assignment
to a keyword the call already passes replaces that keyword's value. No fix is offered when the call has a `**kwargs`
argument, an assignment shares a line with another statement, or a comment sits on its lines.
