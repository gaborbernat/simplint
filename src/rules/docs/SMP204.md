## What it does

Checks for mocks and patches created without a spec: `Mock`, `MagicMock`, `AsyncMock`, `NonCallableMock` and
`NonCallableMagicMock` calls with no positional argument, `patch` calls with fewer than two positional arguments, and
`patch.object` calls with fewer than three. A `spec`, `spec_set`, `wraps`, `autospec`, `new` or `new_callable` keyword,
or a `**kwargs` argument, counts as a spec. Calls match by their last name, so `mocker.patch` and `mock.MagicMock` are
covered.

## Why is this bad?

A mock without a spec accepts any attribute and any call signature, so a test keeps passing after the real code renames
a method or changes its parameters.

## Example

```python
client = MagicMock()
mocker.patch("app.service.fetch")
```

Use instead:

```python
client = create_autospec(Client)
mocker.patch("app.service.fetch", autospec=True)
```

## Fix safety

No fix is offered: the spec is the real object the mock stands in for, and that cannot be inferred from the call.
