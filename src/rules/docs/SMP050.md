## What it does

Checks for module-level constants that only one function uses: names assigned once, with `=` or an annotated assignment,
and referenced only inside the body of a single top-level function or method, including functions nested in it. Skipped
are public names (listed in `__all__`, or without a leading `_` when the module has no `__all__`), names another file in
the run imports or patches, dunder names, class-like names such as `UserId`, constants with a comment on the line
directly above, and constants referenced at import time, including in annotations, defaults and decorators.

## Why is this bad?

A module-level constant suggests the value is shared, so a reader has to search the module to learn that one function
uses it. Defined in that function, its scope matches its use. A comment above the constant, such as one saying it is
built once for speed, keeps it at module level.

## Example

```python
_TIMEOUT = 30


def connect(host: str) -> socket.socket:
    return socket.create_connection((host, 443), timeout=_TIMEOUT)
```

Use instead:

```python
def connect(host: str) -> socket.socket:
    return socket.create_connection((host, 443), timeout=30)
```

## Fix safety

The fix is always unsafe: the value is rebuilt on every call, which costs time for expensive values and gives each call
a new object for mutable ones. When the constant is used once, outside any loop, nested function, lambda or
comprehension, and its value fits on one line, the fix inlines the value at the use, adding parentheses when needed.
Otherwise it declares a local named after the constant, lowercased and without leading underscores, before the statement
that first uses it, and renames the uses. No fix is offered when the constant shares a line with other code or when the
local name already appears in the file.
