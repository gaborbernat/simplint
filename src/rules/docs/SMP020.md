## What it does

Checks the order of functions and classes at module level and in class bodies. A helper that runs only when another
definition is called should sit directly below its first user, the earliest statement that refers to it, and several
helpers of one user follow it in the order the user first refers to them. Module-level helpers are linked to users
through name references, methods through `self.name`, `cls.name` or `ClassName.name`.

Definitions that must exist while the module or class body runs stay where they are: anything referenced at import time
(module-level code, decorators, default values, base classes), names bound more than once (such as a property and its
setter), definitions whose own statement evaluates another module-level name, and everything these call. Annotations and
mutually recursive helpers do not make a user.

## Why is this bad?

Code reads top-down when each function is followed by the helpers it calls. A helper above its caller, or far from it,
makes the reader jump around the file.

## Example

```python
def _parse(line: str) -> tuple[str, str]:
    key, _, value = line.partition("=")
    return key, value


def load(text: str) -> dict[str, str]:
    return dict(_parse(line) for line in text.splitlines())
```

Use instead:

```python
def load(text: str) -> dict[str, str]:
    return dict(_parse(line) for line in text.splitlines())


def _parse(line: str) -> tuple[str, str]:
    key, _, value = line.partition("=")
    return key, value
```

## Fix safety

The fix rewrites the span from the first to the last misplaced statement in the expected order, moving the comment lines
directly above each definition with it, and separates statements with two blank lines at module level and one in a class
body. It is safe when every moved definition is an undecorated function. Moving a class or a decorated function is
unsafe, because decorators, metaclasses and `__init_subclass__` hooks then run in a different order. No fix is offered
when the span holds a comment that is not attached to a definition, or when two statements share a line.
