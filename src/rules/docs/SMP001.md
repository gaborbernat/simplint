## What it does

Checks for own-line comments used as dividers or section headers: comments made only of divider characters (`-`, `=`,
`*`, `#`, `~`, `_`, `+`, `/`, `<`, `>`), comments whose text starts or ends with two identical divider characters such
as `# --- helpers ---`, comments opened with two or more `#` such as `## Setup`, and `# region` / `# endregion` markers.
Trailing comments and comments starting with `#!` are skipped.

## Why is this bad?

A section comment groups code by its position in the file, and nothing keeps the grouping accurate as code moves. A
named function, class or module groups the same code under a name that tools can check.

## Example

```python
# ---------- parsing ----------
def parse_header(line: str) -> str:
    return line.split(":", 1)[0]
```

Use instead:

```python
def parse_header(line: str) -> str:
    return line.split(":", 1)[0]
```

## Fix safety

The fix deletes the comment line and is always safe, since comments do not affect behavior.
