## What it does

Checks for an assignment to a single name that is directly followed by an `if` whose test starts with that name, when
nothing else in the scope reads the name: not after the `if`, and not before the assignment either, such as a closure or
an earlier statement of the same loop. The test starts with the name when the name is the whole test, the operand of
`not`, the left side of a comparison or the first operand of `and`/`or`. Class bodies are skipped, as are values that
are lambdas, `yield`, `:=` expressions, starred or unparenthesized tuples, values that mention the name itself,
assignments sharing a line with other code, a comment between the assignment and the `if`, values continued with a
backslash, module-level names another module in the run imports, and names the function declares `global` or `nonlocal`.

## Why is this bad?

A name that exists only to feed the next test splits one decision over two statements and stays in scope after it stops
mattering. Inlining the value, or binding it with `:=` in the test, keeps the value next to the check that uses it.

## Example

```python
def first_word(text: str) -> str:
    found = re.match(r"\w+", text)
    if found:
        return found.group(0)
    stripped = text.strip()
    if not stripped:
        return ""
    return text
```

Use instead:

```python
def first_word(text: str) -> str:
    if found := re.match(r"\w+", text):
        return found.group(0)
    if not text.strip():
        return ""
    return text
```

## Fix safety

The fix is safe. It deletes the assignment and, when the `if` statement uses the name only in its test, inlines the
value, adding parentheses where precedence requires. Otherwise it writes `name := value` in the test, parenthesized
unless the name is the whole test. The search for other uses covers the enclosing function, or the whole file at module
level, so it misses only importers outside the run.
