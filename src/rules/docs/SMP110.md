## What it does

Checks for `from ... import` statements that name the current package, or a package below it, with an absolute path. A
file counts as part of a package when its directory holds an `__init__.py`. Imports from a parent package and plain
`import a.b` statements are not reported.

## Why is this bad?

An absolute import repeats the package name, so renaming or vendoring the package means editing every such import. A
relative import shows at a glance that the target lives next to the importing module.

## Example

```python
# in package/sub/module.py
from package.sub import sibling
from package.sub.deep import thing
```

Use instead:

```python
# in package/sub/module.py
from . import sibling
from .deep import thing
```

## Fix safety

The fix is safe unless the module has an `if __name__ == "__main__":` block. The relative import resolves to the same
module when the file is imported as part of its package, but a file run directly with `python path/to/module.py` has no
package, and relative imports fail there.
