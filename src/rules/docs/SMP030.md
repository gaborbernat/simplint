## What it does

Checks for private functions and methods whose body, apart from a docstring, is a single call, returned or used as an
expression statement. It covers module-level functions whose name starts with `_`, and such methods of module-level
classes without base classes. Dunder and decorated functions are skipped, as are functions the file never refers to or
refers to anywhere without calling them, for example when passing them as a callback. Methods are matched through
`self.name`, `cls.name` or `ClassName.name`. The arguments of the call are not inspected.

## Why is this bad?

The wrapper adds a name and an extra hop without adding behavior, and a reader has to open it to learn that it calls
something else. Calling the target directly removes the indirection.

## Example

```python
def config_path() -> Path:
    return _make_path("config.toml").resolve()


def _make_path(name: str) -> Path:
    return Path(name)
```

Use instead:

```python
def config_path() -> Path:
    return Path("config.toml").resolve()
```

## Fix safety

No fix is offered, since inlining needs each call site's arguments mapped onto the target's parameters.
