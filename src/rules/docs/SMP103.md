## What it does

Checks modules with `__all__` for top-level functions and classes that have no leading underscore and are missing from
`__all__`. `__all__` is collected from assignments, `+=`, `.extend([...])` and `.append("name")` with string literals;
when any other statement builds it, such as `list(...)` or `.remove(...)`, nothing is reported. Decorated definitions
are skipped, since the decorator may register them, as are names another module in the run imports, pytest hooks
(`pytest_*`), `load_tests`, `setup_module` and `teardown_module`. Test modules (`test_*.py`, `*_test.py`, `conftest.py`
and files under a `tests` or `test` directory) and modules without `__all__` are not checked.

## Why is this bad?

`__all__` declares the public API. A name that looks public but is missing from it leaves readers unsure whether they
may depend on it, and a leading underscore answers that question at every use.

## Example

```python
def exported() -> int:
    return helper()


def helper() -> int:
    return 1


__all__ = ["exported"]
```

Use instead:

```python
def exported() -> int:
    return _helper()


def _helper() -> int:
    return 1


__all__ = ["exported"]
```

## Fix safety

The fix renames the name to `_name` everywhere in the file and is always unsafe: importers outside the run keep the old
name. If the name is meant to be public, add it to `__all__` instead. No fix is offered when the new name already
appears in the file, the old name appears in a string outside `__all__`, or the old name also appears as a parameter,
local, class attribute or attribute access that a text rename cannot tell apart.
