## What it does

Checks for `__init__.py` files that hold anything besides a module docstring. Every statement after the docstring is
reported, including imports and `__all__`.

## Why is this bad?

Code in `__init__.py` runs whenever any submodule of the package is imported, so a heavy or failing import there slows
down or breaks unrelated modules. Re-exports give one object two import paths and invite circular imports.

## Example

```python
"""HTTP client."""

from .client import Client

__all__ = ["Client"]
```

Use instead:

```python
"""HTTP client."""
```

Importers then use `from http_client.client import Client`.

## Fix safety

No fix is offered: removing the code breaks every importer that relies on it, and moving it needs a decision about where
it belongs.
