## What it does

Checks that module-scope variable names match their visibility: `UPPER_CASE` for names listed in `__all__`,
`_UPPER_CASE` for the rest. `__all__` is collected from assignments, `+=`, `.extend([...])` and `.append("name")` with
string literals; without `__all__` every variable counts as private, and when any other statement builds it, such as
`list(...)` or `.remove(...)`, the rule is skipped. A name another module in the run imports keeps its current leading
underscore and only changes case. Dunder names, class-like names such as type aliases, names also bound by an import,
`def` or `class`, names bound only as `for`, `with`, `except` or `match` targets, and pytest's `pytestmark`,
`pytest_plugins`, `collect_ignore` and `collect_ignore_glob` are skipped. Names bound with `:=` are checked.

## Why is this bad?

Upper case tells a reader the name is a module-level value rather than a local. The leading underscore tells them
whether other modules may use it. Deriving both from `__all__` keeps the names in line with what the module exports.

## Example

```python
limit = 3
logger = logging.getLogger(__name__)

__all__ = ["logger"]
```

Use instead:

```python
_LIMIT = 3
LOGGER = logging.getLogger(__name__)

__all__ = ["LOGGER"]
```

## Fix safety

The fix renames every use in the file, including the `__all__` entry, and is always unsafe: importers outside the run,
and string references such as `mocker.patch` targets in unchecked files, keep the old name. No fix is offered when
another module in the run imports the name, the new name already appears in the file, the old name appears in a string
outside `__all__`, or the old name also appears as a parameter, local, class attribute or attribute access that a text
rename cannot tell apart.
