## What it does

Checks for rows in a literal `pytest.mark.parametrize` list or tuple that are not `pytest.param(..., id=...)`. Rows
built elsewhere, such as a module constant passed as the argument values, are not checked, nor are rows of a decorator
that passes `ids=`.

## Why is this bad?

Without an id, pytest names a case after its values or its index, such as `test_values[3-4]`. A readable id says what
the case covers and stays stable when the values change.

## Example

```python
@pytest.mark.parametrize(
    ("value", "expected"),
    [
        (1, 2),
        (-1, 0),
    ],
)
def test_increment(value: int, expected: int) -> None:
    assert value + 1 == expected
```

Use instead:

```python
@pytest.mark.parametrize(
    ("value", "expected"),
    [
        pytest.param(1, 2, id="positive"),
        pytest.param(-1, 0, id="negative"),
    ],
)
def test_increment(value: int, expected: int) -> None:
    assert value + 1 == expected
```

## Fix safety

No fix is offered: a meaningful id describes what the case tests, which cannot be derived from its values.
