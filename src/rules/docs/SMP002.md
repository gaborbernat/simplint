## What it does

Checks for docstrings on functions, methods and classes, at any nesting depth.

## Why is this bad?

A docstring restates what the name, signature and type annotations already say, and nothing checks that it stays
accurate when the code changes. When the reason behind a piece of code is not obvious, a short comment next to that code
explains it better.

## Example

```python
def load_config(path: Path) -> Config:
    """Load the config from the given path."""
    return Config.from_toml(path.read_text())
```

Use instead:

```python
def load_config(path: Path) -> Config:
    return Config.from_toml(path.read_text())
```

## Fix safety

The fix deletes the docstring and the blank lines after it; when the docstring is the whole body, it is replaced with
`...`. The fix is always unsafe, because code that reads `__doc__`, such as doctests or help text built from docstrings,
sees the change. No fix is offered when the docstring shares a line with other code.
