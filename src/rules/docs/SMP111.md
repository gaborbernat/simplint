## What it does

Checks for dataclasses declared without `frozen=True` and `slots=True`.

## Why is this bad?

A mutable dataclass can change under any code holding a reference to it, so a reader cannot trust a value they saw at
construction time. A frozen instance is also hashable. Slots reject misspelled attribute writes and shrink each
instance.

## Example

```python
@dataclass
class Release:
    version: str
```

Use instead:

```python
@dataclass(frozen=True, slots=True)
class Release:
    version: str
```

## Fix safety

The fix is safe when nothing in the run can observe the change: no file assigns or deletes an attribute named like one
of the fields, the class neither inherits nor is inherited from, and its body neither sets attributes nor uses `super`,
`cached_property`, `__dict__`, `__weakref__`, `__slots__`, `__setattr__` or `__delattr__`. Otherwise, or when the
decorator already sets one of the options to `False`, the fix is unsafe. Code that adds a new attribute to an instance
from outside the class is not detected.
