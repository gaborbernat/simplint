## What it does

Checks for `assert` statements whose test is a truthy constant: `True`, a non-zero number, a non-empty string or bytes
literal, `...` or a non-empty tuple. `assert False` and `assert 0`, which always fail on purpose, are not reported.

## Why is this bad?

An assertion on a truthy constant can never fail, so it checks nothing and makes a test look like it verifies more than
it does. A parenthesized `assert (check, "message")` is a non-empty tuple and falls in the same trap.

## Example

```python
def test_save(tmp_path: Path) -> None:
    save(tmp_path / "out.json")
    assert True
```

Use instead:

```python
def test_save(tmp_path: Path) -> None:
    save(tmp_path / "out.json")
    assert (tmp_path / "out.json").exists()
```

## Fix safety

For a two-element tuple without a message, such as `assert (check, "message")`, the fix rewrites it to
`assert check, "message"`. It is unsafe, since the restored check may now fail. Other tuples get no fix. For any other
constant the fix is safe: it deletes the assertion, which never fails, and leaves `pass` when it was the only statement
in its block. No fix is offered when such an assertion shares a line with another statement.
