## What it does

Checks for public module-level names that another file in the run imports but `__all__` does not list. Imports count as
`from module import name`, `module.name` access, dotted strings such as `mocker.patch("pkg.mod.name")`, and entry points
declared in `pyproject.toml`. Names starting with `_`, `__init__.py` files and test modules are skipped. `__all__` is
collected from assignments, `+=`, `.extend([...])` and `.append("name")` with string literals; when any other statement
builds it, such as `list(...)` or `.remove(...)`, nothing is reported.

## Why is this bad?

`__all__` is the list of names a module promises to keep. A name other modules depend on but `__all__` omits looks
private, so a later change can remove or rename it without noticing the importers.

## Example

```python
LIMIT = 3


def shared() -> int:
    return LIMIT


__all__ = ["local"]
```

Use instead:

```python
LIMIT = 3


def shared() -> int:
    return LIMIT


__all__ = ["local", "LIMIT", "shared"]
```

## Fix safety

The fix is safe. It appends the missing names to the list or tuple of the last `=`, annotated or `+=` binding of
`__all__`, one per line when that literal spans several lines, or adds `__all__` at the end of the module when there is
none. Importers outside the run are not seen.
